# HireFlow — Applicant Management System

A full-stack recruiter workspace with a dark navy/cyan interface, dashboard metrics, applicant CRUD, hiring pipeline, jobs CRUD, analytics, CSV export, JWT login, role-based API access, request validation, and security middleware.

## Requirements
- Node.js 20+
- MongoDB Community running locally, or a MongoDB connection URI
- Terminal and VS Code

## Project structure
- `client/` — React + Vite UI
- `server-business/` — Express + MongoDB API

## 1. Configure the backend
Open a terminal:
```bash
cd server-business
cp .env.example .env
```
Edit `server-business/.env` and set a long random `JWT_SECRET`. Default local MongoDB URI is `mongodb://127.0.0.1:27017/hireflow`. Never commit `.env` or share credentials.

Install dependencies:
```bash
npm install
```
Create an initial admin account by adding these temporary values to `.env` (use your own values; password must be at least 12 characters):
```env
BOOTSTRAP_ADMIN_NAME=Your Name
BOOTSTRAP_ADMIN_EMAIL=you@example.com
BOOTSTRAP_ADMIN_PASSWORD=use-a-unique-password-12chars
```
Then run:
```bash
node scripts/create-admin.js
```
After success, remove the three `BOOTSTRAP_ADMIN_*` values from `.env`. This script will not overwrite an existing account.

Run backend checks and server:
```bash
npm run check
npm test
npm run dev
```
The API uses `http://localhost:5001`; health check: `http://localhost:5001/api/health`.

## 2. Run the frontend
In a second terminal:
```bash
cd client
npm install
npm run dev
```
Open `http://localhost:5173` and sign in using the admin credentials you created.

Optional API override: create `client/.env` with `VITE_API_URL=http://localhost:5001/api`.

## Features
- Dashboard overview and real API metrics
- Applicant create, read, update, delete (delete is admin-only)
- Search, status filter, CSV export
- Jobs create, edit, list, delete
- Recruitment analytics and pipeline breakdown
- JWT-protected endpoints and role authorization
- Responsive mobile layout

## Important notes
- MongoDB must be running before starting the API.
- Public registration creates a regular `user` account; it does not grant recruiter/admin privileges. Use the bootstrap script for the initial administrator.
- Applicants currently connect to jobs through matching the applicant's `role` text to the job `title`; a dedicated `jobId` relationship can be added as a later enhancement.
- Email delivery requires SMTP configuration and is not enabled by default.
- This is a development starter, not a production deployment. Before production, add HTTPS, secret management, deployment-specific CORS, backups, monitoring, security review, and stronger automated end-to-end tests.

## 3. Deployment (Vercel + Render + MongoDB Atlas)

This repository includes `render.yaml` for the API and `client/vercel.json` for Vite SPA routing. Deployment still requires you to sign in to the hosting providers and configure cloud database credentials.

1. Push the extracted `HireFlow/` folder to a GitHub repository. Do not commit `.env` files or secrets.
2. Create a MongoDB Atlas cluster and database user. Add the Render service's outbound access as allowed in Atlas (for a quick demo, Atlas documents temporary broad access; restrict it for production). Copy the Atlas connection string for the `hireflow` database.
3. In Render, create a Blueprint from your GitHub repository and use the included `render.yaml`. Set `MONGO_URI` to the Atlas connection string and `CLIENT_URL` to the final Vercel frontend URL. `JWT_SECRET` is generated by the Blueprint. Deploy the service and verify `/api/health`.
4. In Vercel, import the same GitHub repository. Set the project Root Directory to `client`, Framework Preset to Vite, and add `VITE_API_URL` with the full API base URL, e.g. `https://YOUR-API.onrender.com/api` (replace with your actual Render URL). Deploy.
5. Update Render's `CLIENT_URL` to the exact Vercel origin (no trailing path), then redeploy the backend.
6. Create the first administrator on the deployed API using a secure one-time method. Do not expose bootstrap credentials in the repository. The included `scripts/create-admin.js` runs against whichever `MONGO_URI` is in the environment; only run it from a trusted local terminal configured with the production URI, and remove temporary bootstrap variables immediately afterward.
7. Test login, applicant CRUD, job CRUD, analytics, and refresh behavior on the deployed site. Do not enter real candidate data until access control, backups, and privacy requirements have been reviewed.

### Production cautions
- Free hosting plans may sleep or have usage limits; cold starts can occur.
- Keep secrets in provider environment settings, never in frontend `VITE_*` variables.
- `VITE_API_URL` is public client configuration, not a secret.
- A passing syntax check is not the same as a successful production build or end-to-end test. Run `npm test` in `server-business` and `npm run build` in `client` before relying on the deployment.
